## 6. Observations on the run — recorded, NOT acted on

Facts read out of the written output after the single run.  No rule, range, mapping
entry, validation status or label was changed in response.

1. **`fusion` predicted zero Applicable cases** (0 TP, 0 FP -> `precision` `N/A`,
   `recall` 0, `F1` 0, coverage 0.1452, Unknown rate 0.8548).  All 67 non-empty
   impact paths in the run have `P_i = Unknown`; the only `P_i = True` path is the
   empty (vacuously true) nginx path, and there `B = Unknown` (`CVE-2021-23017`).
   The mechanism is visible in the records: `B = True` but `P_i = Unknown` because
   the controlling conditions are `observable: false` (no probe) or `pending`
   (G7 gate) — e.g. `CVE-2023-2745__vuln` (`B=True`, `p_crafted_mo_present`
   Unknown), `CVE-2015-3440__vuln` (`B=True`, `p_comments_open_on_post` `pending`,
   `p_content_column_is_text_64k` no probe), `CVE-2021-41773__weakened_249`
   (`B=True`, both path conditions no probe).  This is the observability ceiling
   the design anticipates (D-031 / CURRENT_STATE §46; protocol R1), but its
   **magnitude** — zero positive conclusions, so fusion is dominated on
   recall/coverage by the single-source baselines (which are identical to each
   other) — is the headline result of the run.
2. **The Not-Applicable branch-b rule never fires on real data.**  All six branch-b
   cases (`CVE-2021-41773__default_249`, `CVE-2019-6340__both_off_869`,
   `CVE-2024-10924__9_1_1_1_2fa_off`, `CVE-2020-13671__config_off`,
   `CVE-2020-12640__config_off`, `CVE-2020-12641__config_off`) are `Unknown` for
   `fusion` (U_N).  Branch b requires `product_identified` and a determined path
   scope with every path `P_i = False`; here the identity/version is not observable
   (Roundcube/Drupal) and/or the gating precondition is `pending`/no-probe, so
   `P_i` is `Unknown` rather than `False`.  All 9 `fusion` Not-Applicable cells are
   branch **a** (`B = False` from a source range).  The branch-b rule is covered by
   the fixture, not by the benchmark.
3. **`cpe_only` / `nvd_only` / `http_version_only` are one vector** (§5), so the
   "compare 4 single sources" set currently yields **three** distinct prediction
   vectors: the CPE/NVD/HTTP-version vector, `advisory_only`, and `fusion`.
   `http_version_only` reads the CPE table as its declared lookup (documented
   decision, README "Decisions taken" §1/§8), which makes the coincidence
   structural rather than a measurement.
4. Expected, recorded outcomes (not defects): `CVE-2017-1001000__fixed` is the only
   case where `advisory` and `NVD/CPE` disagree; advisory precedence resolves it to
   `Not Applicable` (`fusion` TN) while `cpe_only` counts an FP — the D-031
   ruling-1 consequence.  `CVE-2021-23017__backport_na_a` is `Unknown` for every
   method (E5 distro-scope mismatch), as D-031 ruling 2 expects — i.e. the
   benchmark's "already-patched backport" negative is not decided by any method.
   `CVE-2019-6340`'s 4 cases and the Roundcube/Drupal cases are `Unknown` for all
   methods (no accepted version/identity observation).
5. `CVE-2023-2745` behaved as intended on the two real cases and the new key was
   not reached: `6.2.0` -> advisory verdict `True` (fusion `B=True`, path stage
   Unknown), `6.2.1` -> `False` (branch a, Not Applicable).  The `out_of_scope`
   branch is only reachable for a non-6.2 observed version, which no benchmark case
   has (behaviour covered by `CVE-9000-0013`).
